# Sourcemark v0.1 — evidence at the operation

Design baseline: `be76b0570bf59d31dbe56903192a79b4b2a8b730`, clean WIP checkout observed before this design. This document supersedes broader release promises in product-contract.md where scope differs. It is an implementation assignment, not a claim that acceptance already passes.

## Decision and customer
Build a small deployable evidence-delivery product for a developer already using Claude Code and maintaining a code graph or structured project knowledge. The job is: when the agent attempts a supported search, supply the better, scoped evidence without asking it to remember another tool. Keep a usable CLI for inspecting attributable claims. Do not sell a universal truth engine.

This retires the risk that available authoritative evidence is missed at action time; the cheapest alternative is another prompt reminder plus manual lookup; automatic operation-bound delivery is chosen because reminders are already present and fail. We reuse the existing hook, receipt and CLI architecture. No second routing framework, service daemon, embedding deployment or runtime model classifier.

## Release scope
1. One production-quality vertical slice: Claude Code structured `Grep` call → trusted configured structural provider → bounded evidence → actual hook response → scoped receipt. Default is augmentation, not suppression: retain the original search and its permissions. This avoids claiming a graph answers arbitrary regex searches.
2. Exact `Read` of a configured canonical context file → matching locally registered claims and their sources injected at the same tool boundary. Historical/memory lookup is explicit subject/scope via `sourcemark context`; no claim to detect all past-decision questions. Other hosts may call this CLI; they do not acquire hook enforcement by doing so.
3. A small actionable context queue over explicit claim records: expired, drifted, conflicted, missing evidence. Up to five shown; total retained; inspect → explicitly reverify or retire → recheck. No automatic prose extraction or edits to original documents.
4. Safe install, doctor, trace and ownership-aware removal; portable local package and a real setup walkthrough.
5. Evidence and outcome reporting: coverage, provider latency/failures, delivered contacts, annotated stale-answer outcomes per ten observed sessions, and the paired synthetic pilot. Correctness is not inferred from contact count.

Defer MCP server, additional host adapters, arbitrary Bash interception, automatic semantic claim mining, universal completion blocking, dashboards and automatic policy learning. Preserve existing tested functionality as compatibility, but do not enable the failed prompt router as the default Sourcemark interception mechanism. Do not delete unrelated access gates. The eight field failure categories remain explicit-metadata fixtures and honest support/limitation rows, not eight new subsystems.

## Concrete changes from baseline
- `src/tool-evidence.js::selectToolEvidence` is the right starting seam, but selection and execution must be separated for testability and permission ordering. Keep this module; no generic plugin framework.
- `src/claude-code.js::handleClaudeHookLocked`: current WIP computes `extra` but drops it on the ordinary allowed return. Deliver evidence in `hookSpecificOutput.additionalContext` on that path and combine it with CORRECT output. Tests must execute the public hook CLI and assert the returned bytes, not just provider-selection helpers.
- Do not run providers when existing Sourcemark policy returned DENY or ASK. Return that policy result unchanged. For permitted/pass-through calls, return context without an explicit `permissionDecision: allow`: Sourcemark must not bypass the host's own permissions. A configured provider is separately authorized read-only execution, not permission to execute the intercepted operation. It may run before the host later asks or denies the original operation; no host-denial-aware suppression is claimed without that host capability.
- Replace public help/README/init output with Sourcemark. Keep one public identity constant. Historical module filenames may remain internal; public CLI is `sourcemark`. Do not rebrand old immutable evidence artifacts.
- `src/context-integrity.js`: confine and validate source paths before stat/read, including realpath/symlink escapes. A digest detects changed bytes; it does not verify claim meaning. A source's self-declared `live` tier is not proof of live observation.

## Trust boundary and configuration
Repository documents, provider outputs, and checked-in configuration are untrusted data. A repository clone must never authorize executable provider commands merely by containing providers.json. Explicit initialization must preview provider IDs, executable/arguments, roots, output limits and data exposure. Record local consent to the normalized execution configuration digest in a user-owned state directory outside the checkout, keyed by canonical worktree identity. Never import consent from repository files, including ignored or forcibly tracked state. This does not protect against malicious code already running as the same user. A changed executable/argv/provider policy invalidates consent and yields UNKNOWN without execution until explicitly reconciled. For project-owned provider scripts, bind script bytes too; changing a script must not inherit approval. No `eval`, shell interpolation, command extracted from prose, package installation or credential collection.

Ship a provider protocol and a tiny real local read-only example adapter. The example may use an existing index, but must not return hardcoded fixture answers. Provider transport is argument-vector execution, documented as trusted code with the user's process privileges, NOT sandboxing. Credentials, network policy and external service provisioning stay operator-owned. Do not promise generic remote integrations until tested.

Use a single public `.sourcemark` configuration/state namespace for fresh installs. Existing `.leadline` installations are detected and require an explicit previewed migration; never silently load both or delete the old directory. Consent lives outside the checkout; repository-local runtime artifacts are ignored by Git. Gitignore is hygiene, not authorization. Maintain atomic writes and restrictive modes. Redact output before durable storage; retain hashes and bounded sanitized excerpts, not unlimited raw provider documents. No telemetry.

## Matching, execution and result contract
Match only known structured operations. For Grep v0.1, admit a simple identifier pattern and explicit existing target. Regex/metacharacter searches, content-mode/options with unsupported semantics, ambiguous/omitted targets, and non-indexed extensions pass through without a coverage claim. Do not parse arbitrary shell pipelines. Directory calls require provider coverage metadata and are labeled partial when not all files/languages are covered; partial graph evidence can be injected but never replaces full search or certifies absence.

Canonicalize configuration root, actual cwd/worktree and target separately. v0.1 may require initialization per worktree rather than sharing settings; mismatches yield UNKNOWN, not cross-worktree answers. Validate canonical target, provider roots and returned sources against the same boundary. Provider identity and index revision are bound to target checkout; a fresh timestamp alone cannot make an index current. Wrong project/revision/target, future timestamps, invalid schema, stale index and provider errors never satisfy a contact's evidence-quality check.

Request fields: schema_version, execution_id, project/worktree identity, target, operation, exact query and request digest. Response echoes request identity and supplies index identity/coverage, observed_at, result status, source-located evidence and truncation information. A reported zero counts only when supported by applicable complete coverage and a tested positive control; otherwise UNKNOWN. No substring match alone constitutes semantic verification. Report provider-asserted scope versus locally verified path/revision honestly.

Keep provider deadline at or below the existing 1500ms bound and output at or below 16KiB; bounded sanitized injection may be smaller with an explicit truncation indicator and receipt ID. Reject oversized/malformed results. Provider timeout must clean up owned children; use a short-lived supervised child/process group with bounded termination escalation and test a child that ignores initial termination. No daemon/job framework is needed; test the process tree, not only the immediate child. Do not retain the state lock across an unbounded call. Host hook timeout can fail open: document this rather than claiming universal fail-closed protection.

Each result carries status `delivered`, `unknown`, `unsupported`, or `policy-skipped`, with reason and timing. Record failures as well as success. Dedupe by session + actual turn identity + call ID + canonical args + config digest + target identity. Repeated identical callback reuses one receipt; conflicting reuse is UNKNOWN; no session-wide unlock. Under the existing lock persist a pending execution identity before launch; commit the terminal result under lock. A duplicate pending record returns UNKNOWN without replay. Persist this identity so crash recovery cannot silently credit a second attempt; an indeterminate attempt is UNKNOWN rather than claimed exactly-once execution. Retain existing PostToolUse binding for the original tool separately.

## Attributable context without fake certainty
Keep exact subject/scope selection. Sources have operator-configured authority; claims have identity, locator, writer agent/model/session, validity interval, source digest and referenced evidence. Missing attribution remains unknown, not fabricated. Model mismatch appears as an opt-in notice/inspection field, not an alarm or distrust score.

Separate lifecycle (active/retired/superseded), observation time and verification time. Explicit same-scope supersession is validated and honored even across sources according to configured authority; a random newer lower-authority claim cannot win. Detect cycles, missing supersession targets, duplicate IDs and equally authoritative conflicting active claims. Return alternatives and uncertainty when resolution is not justified. Do not promote stale lower-tier evidence when the relevant authoritative observation failed.

Deployment identity and effective-config tier are evidence attributes where applicable, not mandatory fiction for every live claim. Static imported observations must say they are snapshots. Read-reference availability, digest and recorded control outcomes are mechanically checked; their truth remains attributable to the observer. A boolean `complete: true` or a control name alone is not an independently reproduced control. User-visible output must distinguish mechanical checks from observer assertions: “attributed claim; source unchanged; recorded verification by X,” not an unqualified SUPPORTED/truth verdict. Queue closure means the recorded defect was resolved, not that Sourcemark proved the claim true.

Queue items derive from these exact records. `reverify` accepts new explicit evidence/provenance, never just refreshes today's date; `retire` preserves history. Store closure events separately from immutable observations. Re-running detection closes only a resolved finding; unreadable registry cannot shrink backlog. Read-frequency ranking uses observed source-read contacts with declared window; otherwise rank by severity/age and label frequency unavailable. Reports separate original cohort remaining, resolved and newly arrived findings. No forced count reduction.

## Installation and recovery
Package supports Node's declared version range, no global install required. Produce an npm pack tarball locally, install it into a temporary prefix, run `sourcemark --help`, init preview, install, repeat install, doctor, hook, context, queue and remove. No public registry publishing.

Init validates everything before mutation, preserves unrelated hooks/settings/config/packs/ignore rules, records exact owned entries and before/after hashes, and writes atomically. Repeated initialization is idempotent. Edited owned entries trigger explicit conflict rather than overwrite. Remove previews and deletes only unchanged owned wiring; preserves user edits, receipts, context and unrelated settings by default. Tests cover interruption between settings/manifest writes and safe retry. Rollback is removing the owned hooks/restoring the recorded matching settings change, not restoring an entire stale settings file over user edits.

Doctor validates schema, paths, executable consent, host capability and provider positive/negative controls. It reports which checks actually ran. No silent network calls outside a consented provider. No live user installation during this build.

## Acceptance and proof
Dae builds the runtime changes; Pebble owns product design, experiment and acceptance review. Freeze one integrated local head and retain actual command output. Run existing baseline tests plus:
- Public CLI installed from the local tarball; no source-checkout fallback; no private paths, hosts, data or seed history in new release files.
- Actual PreToolUse CLI: supported provider answer reaches additionalContext; regular Grep still receives normal host permission handling; Sourcemark-policy DENY/ASK invokes no provider; unsupported cases pass through.
- Empty/wrong-scope/stale/revision-mismatched/oversized/malformed/timeout results; duplicate callback and crash ambiguity; changed consent digest; malicious repository argv/script; symlink escapes; mixed-language directory; structured-zero positive control.
- Same operation in two worktrees/sessions does not share evidence. Source text that says to execute a command never becomes executable configuration.
- Claim-level expiry inside fresh file, explicit dated supersession, deployed-vs-checkout/effective-config snapshot distinction, partial evidence and control failure, provenance mismatch without rejection, stale handoff, instrument failure, queue closure with arrivals.
- Init twice and remove with neighboring hooks/config and operator edits; interrupted install recovery. Existing access/map gates remain intact.

Benchmark has two distinct layers. Existing fourteen-case isolated context pilot tests supplied-context assistance only, not real hook interception; current OFF-first order is a declared deviation and all failures stay in denominator. ON must use actual product output and no hand-authored answer summary; do not transform grading keys into claim registries. If fixtures need explicit metadata, add the same evidence-derived registry to BOTH arms and rerun both: do not retrofit only ON. Keep the original pilot artifacts.

Separately run an actual installed-hook task with supported and unsupported searches, a known-present control and wrong-scope provider. Retain host-visible response/trace and agent final evidence citations. Unit tests alone cannot certify host delivery. If the actual Claude host is unavailable, name actual Claude delivery AND permission behavior unverified, blocking the Claude-integrated release claim; a local package/CLI completion can be reported separately with that limitation; do not substitute an MCP demo. Report latency, extra calls, false blocks, correct/stale/abstention/failure counts and no-benefit outcomes. Do not delay finishing the useful vertical slice to invent a significance claim.

One final handoff includes integrated SHA/tree/base, design support matrix, installed-package checks, paired artifacts/results/limitations, rollback, and remaining defects. Nothing is pushed or installed live before owner review. No intermediate review gate is added.
